# 다음 개발 세션 인수인계

## 구현 현황 (2026-09-20)

로컬 2인 MVP 구현 완료. `npm start`로 실행하고 `npm test`로 판정 및 입력 테스트를 실행한다. 화면 흐름과 밸런스는 아래 기준을 따른다. 실행·구조는 루트 README, 브라우저 검수 범위는 `docs/testing.md`를 참고한다. 아래 시작점은 개발 전 기록이다.

## 시작점

`game-design.md`를 규칙의 기준으로, `asset-guide.md`와 `assets/manifest.json`을 그림 사용의 기준으로 읽는다. 현재 게임 코드는 없으며, `assets/preview.html`은 에셋 확인용 정적 페이지다. 기존 `docs/github-pages-publish.md`는 이전 프로젝트의 배포 참고 자료로 이번 게임을 이미 배포했다는 뜻이 아니다.

사용자는 **한 기기 로컬 2인·둥글고 귀여운 손그림**을 확정했다. 다음 세션은 이 조건으로 바로 구현한다.

## 제안 구조

로컬 MVP는 HTML/CSS/JavaScript와 Canvas 2D 경기장, DOM 메뉴·조작 버튼으로 충분하다. 별도 라이브러리나 버전을 이번 문서에서 확정하지 않는다.

```text
index.html          메뉴와 접근 가능한 조작 버튼
styles.css          화면 배치, 터치 버튼, 반응형
src/config.js       기획서 밸런스 상수
src/state.js        화면 상태, 라운드, 역할 교대
src/simulation.js   순수 게임 판정과 물 묶음 관리
src/input.js        키보드, 독립 pointer 입력
src/render.js       Canvas 그림 및 상태 표시
assets/             이번 세션에서 준비한 이미지와 SVG
```

문서의 경로는 이후 생성할 제안 구조다. 현재 존재한다고 가정하지 않는다. 에셋 경로는 프로젝트 하위 경로 배포에 대응하도록 상대 경로로 사용한다.

## 상태와 시계

화면 상태: `SETUP → COUNTDOWN → PLAYING → ROUND_RESULT → COUNTDOWN → PLAYING → MATCH_RESULT`. `ROUND_RESULT`에서 두 명이 준비해야 진행. `PAUSED`는 이전 상태와 게임 시간을 저장한다.

게임 시간은 단조 증가 시계를 이용하며 멈춘 시간은 제외한다. 화면이 숨겨지거나 포커스를 잃으면 로컬 모드는 일시정지하고 눌린 입력을 해제한다. 복귀 시 명시적 재개 버튼으로 이어 간다. 프레임이 늦어져도 물 생성 횟수와 타이머가 프레임 수에 의존하면 안 된다.

주요 상태: `roundIndex`, `receiverPlayerId`, `scoresMl[2]`, `elapsedMs`, `cupLane`, `cupMove`, `pendingCupLane`, `sourceLane`, `sourceMoveReadyAt`, `nextEmissionAt`, `dirtyState`, `dirtyReadyAt`, `dirtyUsesRemaining`, `burstId`, `penalizedBurstIds`, `packets[]`.

물 묶음: `{id, lane, kind: clean|dirty, emittedAt, arrivesAt, volumeMl, burstId?}`. 발사 시점에 레인·종류를 복사하며 이후 수정하지 않는다.

### 이벤트 순서

1. 도착 시각이 45,000ms 이상인 묶음은 판정하지 않는다. 종료 시각에는 종료가 최우선이다.
2. 나머지 이벤트는 시간순으로 처리한다. 같은 시각이면 컵 이동 완료 → 유효 입력 → 똥물 상태 전환 → 물 발사 → 물 도착 순서다.
3. 첫 물은 플레이 시작 100ms에 발사하고 이후 100ms 간격. 도착은 발사 시각 +650ms.
4. 똥물의 발사 구간은 `[활성화+700ms, 활성화+1300ms)`이다. 600ms 안의 발사 이벤트만 갈색 묶음이 된다.
5. 컵 이동 중 마지막 입력을 저장하되, 완료된 위치와 같으면 새 이동을 시작하지 않는다. 수도꼭지 잠금 중 입력은 대기시키지 않는다.

렌더링은 물 묶음의 `(현재 시각-발사 시각)/650`으로 낙하 위치를 그린다. 긴 세로 물줄기 SVG는 장식용이며 전체 높이에 하나의 판정 상자를 두지 않는다. 발사 레인이 바뀔 때 옛 물과 새 물이 각각 떨어져야 한다.

## 구현 순서와 완료 기준

1. **기본 화면과 로컬 입력**: 메뉴, 3레인, 컵과 캐릭터, 두 조작 패널. 두 손가락을 동시에 눌러도 상대 입력을 빼앗지 않는다.
2. **깨끗한 물과 점수**: 프레임 속도와 관계없이 일정 발사·낙하·도착 판정. 수도꼭지를 이동해도 기존 물은 원래 레인 유지.
3. **똥물**: 예고·레인 잠금·갈색 발사·사용당 한 번 감점·쿨다운·잔여 횟수. 물이 30mL일 때 맞아도 0 아래로 내려가지 않는다.
4. **한 판 완결**: 45초 종료, 기록 보존, 교대 준비, 2라운드, 결과, 무승부, 재경기.
5. **미술과 반응형**: 에셋 장착, 컵 채움 마스크, 효과, 버튼 피드백. 작은 화면에서도 점수와 버튼이 겹치지 않는다.
6. **검수**: 아래 시나리오 및 실제 태블릿 멀티터치. 사용자가 배포를 요청하면 배포 방식 결정 후 진행.

### 필수 검증 시나리오

- 같은 레인에서 첫 물은 750ms에 +10mL, 650ms에는 아직 0mL.
- 마지막 물 도착은 44,950ms. 깨끗한 물을 한 번도 놓치지 않으면 443묶음 = 4,430mL. 45,000ms 이후 도착분은 0.
- 컵 이동 완료와 도착이 같은 시각이면 새 레인으로 받는다.
- 이미 발사된 물은 수도꼭지 이동 뒤에도 이전 레인으로 떨어진다.
- 첫 6초 이전, 쿨다운, 횟수 소진 시 똥물 사용 거부. 정상 사용 한 번에 횟수 1 감소.
- 하나의 똥물 사용에서 여섯 묶음을 맞아도 총 100mL만 감소. 피한 묶음은 감점 없음.
- 1라운드 1,000mL, 2라운드 900mL이면 1라운드 받는 사람이 승리. 같으면 공동 우승.
- 일시정지·숨김·복귀 때 시간과 투사체가 건너뛰지 않는다. 재경기에는 이전 입력이나 물이 남지 않는다.
- 60Hz와 120Hz에서 같은 입력 기록의 점수가 같다.
- 터치 2개, 키보드 동시 입력, 키 반복, `pointercancel`, 창 포커스 해제 확인.

## 그림 배치

논리 경기장 960×540, 조작 패널은 별도 DOM 영역. 레인 컵 중심 x는 160/440/720, 컵 입구 y=380, 물 시작 y=100. 캐릭터는 컵 오른쪽에 둔다. SVG 컵 외곽 128×144 기준 입구 중심은 (54,29), 수면 마스크는 `asset-guide.md`를 따른다.

캐릭터 PNG의 외곽 투명 여백은 판정에 쓰지 않는다. 첫 구현에서 손 위치에 맞춘 시각적 배치를 조정하되 게임 판정 좌표는 컵 중심에 고정한다. 이미지 자체에 컵을 합성하지 않아 컵 색과 수위를 독립 제어할 수 있다.

## 온라인이 선택되는 경우

방 코드, 2인 준비, 역할 배정, 서버 기준 라운드 시간·점수·물 상태, 연결 끊김 처리부터 설계한다. 클라이언트는 점수를 보내지 않고 레인 선택/똥물 요청만 보낸다. 호스트 판정 방식과 서버 판정 방식의 비용·공정성을 검토한 뒤 한 방식을 택한다. 양쪽이 자기 시계로 독립 판정하지 않는다. 해당 범위는 이번 로컬 초안에 구현되어 있지 않다.
